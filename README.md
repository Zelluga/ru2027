# Telegram Mini App «2027» — совместный учёт расходов

Мини-приложение для Telegram: группа до 6 человек ведёт общие расходы в отдельных
вкладках, видит итоги по каждой вкладке и получает изменения на всех устройствах
(синхронизация ≤ 5 с). Валюта — российский рубль (₽), интерфейс — на русском,
дизайн — «пилюльный» (pill-UI).

- **Стек:** Node.js 24, только встроенные модули (`node:http`, `node:sqlite`, `node:crypto`) — без внешних зависимостей.
- **БД:** SQLite (файл `data/app.db`), таблицы `tabs` и `expenses`.
- **Права:** удаление вкладки — только владелец `@Depenz`; удаление записи — только её создатель (по Telegram ID).
- **Лимит:** не более 10 вкладок.

# Пошаговый запуск

## Шаг 1. Создайте бота в BotFather

1. Откройте [@BotFather](https://t.me/BotFather) в Telegram.
2. `/newbot` → задайте имя (например `2027`) и username бота (например `depenz_2027_bot`).
3. Скопируйте выданный **токен** вида `123456789:AA...`. Он понадобится в шаге 2.

> Если приложение открывается не через бота, а по прямой ссылке, у клиента не будет
> валидного `initData`. Поэтому открывать Mini App нужно через кнопку/меню бота (шаг 5).

## Шаг 2. Настройте конфигурацию

В терминале (PowerShell):

```powershell
cd C:\Users\Denis\Documents\deepseek-harness\default-workspace\2027-mini-app
Copy-Item .env.example .env
```

Откройте `.env` и заполните минимум:

```ini
BOT_TOKEN=123456789:AA...      # токен из BotFather
OWNER_USERNAME=Depenz          # владелец вкладок
OWNER_TG_ID=                   # Telegram ID владельца (рекомендуется)
# ALLOWED_TG_IDS=111,222,...   # (опционально) белый список
PORT=8787
DEV_MODE=0                     # 1 — только для локальной отладки без реального initData
```

## Шаг 3. Запустите сервер

```powershell
npm start
# или: node server.js
```

Сервер слушает `http://0.0.0.0:8787`. При первом запуске создаётся `data/app.db` и
автоматически заводятся две вкладки: **«Падл-пенис»** и **«Сука,Сочи»**.

**Проверка локально:** откройте `http://localhost:8787/` в браузере. Если хотите
потыкать интерфейс без реального Telegram — временно поставьте в `.env` `DEV_MODE=1`
(только локально!) и перезапустите сервер.

## Шаг 4. Получите HTTPS-адрес (нужен для Telegram)

Mini App в Telegram открывается только по HTTPS. Два варианта:

**A. Локальная разработка — туннель** (запустите в отдельном терминале):

```powershell
# ngrok
ngrok http 8787
# или cloudflared
cloudflared tunnel --url http://localhost:8787
```

Скопируйте выданный `https://....ngrok.io` (или `.trycloudflare.com`).

**B. Продакшен — хостинг с HTTPS.** Задеплойте папку на сервер/VPS (Render, Railway,
VPS + Caddy/nginx), запустите `npm start`, домен оберните в HTTPS. В Telegram-настройки
впишите публичный `https://ваш-домен/`.

## Шаг 5. Откройте Mini App через бота

Самый простой способ — кнопка меню бота (однократно, из терминала):

```powershell
curl.exe -X POST "https://api.telegram.org/bot<ТОКЕН>/setChatMenuButton" `
  -H "Content-Type: application/json" `
  -d '{"menu_button":{"type":"web_app","text":"Открыть 2027","web_app":{"url":"https://ВАШ-АДРЕС/"}}}'
```

Либо кнопка в сообщении:

```powershell
curl.exe -X POST "https://api.telegram.org/bot<ТОКЕН>/sendMessage" `
  -H "Content-Type: application/json" `
  -d '{"chat_id":"<ВАШ_CHAT_ID>","text":"Открыть приложение:","reply_markup":{"inline_keyboard":[[{"text":"2027","web_app":{"url":"https://ВАШ-АДРЕС/"}}]]}}'
```

Также можно зарегистрировать Mini App через BotFather командой `/newapp` и получить
прямую ссылку вида `t.me/<bot_username>/<app_short_name>`.

## Шаг 6. Проверьте на устройствах

Откройте бота → кнопку/меню → «2027» на каждом из 6 устройств (Android + iPhone).
Все должны видеть одинаковые вкладки и записи; изменения у одного появляются у остальных
в течение 5 секунд (опрос каждые 3 с).

# Быстрая проверка ключевых требований

| Критерий | Где проверить |
|---|---|
| Две вкладки при первом запуске | открыть приложение → вкладки «Падл-пенис», «Сука,Сочи» |
| Лимит 10 вкладок | создать 10 → кнопка «+ Добавить вкладку» заблокирована, текст «Достигнут лимит в 10 вкладок» |
| Удаление вкладки только @Depenz | у не-владельца кнопки нет; прямой `DELETE /api/tabs/:id` от чужого → 403 |
| Удаление своей записи | кнопка удаления есть только у своих записей (`createdByTgId === me.id`) |
| Удаление чужой записи → 403 | даже @Depenz не удалит чужую запись через API |
| Итоги только по активной вкладке | внизу: общая сумма + Денис/Алексей/Кирилл |
| Суммы в ₽ | формат вида «1 250,00 ₽» |
| Каскадное удаление вкладки | удаление вкладки удаляет все её записи у всех |

# Самопроверка (тесты)

В комплекте два скрипта самопроверки (без внешних зависимостей):

1. **HMAC-валидация initData** — проверяет подпись, подделку, срок действия, неверный токен:
   ```powershell
   node test-initdata.mjs
   ```

2. **REST API** — 30 проверок: сид вкладок, лимит 10, дубликаты, права (403 для чужих),
   каскадное удаление, итоги. Нужен запущенный сервер в режиме `DEV_MODE=1` (имитация
   пользователей через `user=` в заголовке initData):
   ```powershell
   # терминал 1 (отдельная тестовая БД):
   $env:DEV_MODE='1'; $env:DB_PATH='./data/test.db'; $env:PORT='8791'; node server.js
   # терминал 2:
   $env:BASE_URL='http://127.0.0.1:8791'; node test-api.mjs
   ```

# Примечания по безопасности

- Подпись `initData` проверяется на сервере HMAC-SHA256 с секретом от токена бота;
  проверяется и срок действия (`AUTH_MAX_AGE_SECONDS`, по умолчанию 24 ч).
- Проверка прав на удаление выполняется **на сервере**, клиентская скрывает только кнопки.
- `DEV_MODE=1` пропускает проверку подписи — используйте **только локально**, в проде ставьте `0`.
- Токен бота храните в `.env` и не коммитьте в репозиторий.
